# REACH EWS · Facility and health-data provenance

This release separates **forecast/hazard data**, **facility registry data**, and **health-service context** so the dashboard does not imply a level of evidence that the inputs do not support.

## Zambia facility registry

Primary runtime public source:
- Zambia NSDI Health Facilities ArcGIS layer
- Service layer: `https://www.map.gov.zm/arcgis/rest/services/Health/NSDI_Health/MapServer/0`

Bundled project source:
- `zambia_pilot_facility_details.xls`
- Used as a REACH project fallback/enrichment source for Senanga and Sinazongwe.

The app merges project and online registry records by normalised facility name and prefers the project record when the same named facility appears in both sources.

## Zambia HMIS context

Bundled compact file:
- `zambia_pilot_hmis_context.csv`

This is a Senanga/Sinazongwe subset of the uploaded district-month HMIS dataset. It is used for **district-level context only**. It is not attributed to individual facilities and is not used to manufacture a facility readiness score.

## Brazil facility registry

Runtime public source:
- CNES / DATASUS Open Data API
- Endpoint: `https://apidadosabertos.saude.gov.br/cnes/estabelecimentos`
- Documentation: `https://apidadosabertos.saude.gov.br/`

The app queries active establishments by municipality code for Recife and Palmares and uses reported facility coordinates for the point-specific forecast screen.

## Forecast sources

The existing EWS forecast architecture is retained. It includes ECMWF/Open-Meteo, NOAA/Open-Meteo, GloFAS/Open-Meteo and the climate-driver sources already documented in the dashboard.

## Interpretation rule

A facility point inherits no readiness assumptions from its location. The current facility output is therefore described as **facility-specific hazard/exposure**. An operational-risk score should only be introduced after explicit readiness/access inputs (for example staffing, electricity/backup, WASH, cold chain, service availability or access disruption) are integrated and documented.

## V8 model-comparison, labelled contours and facility visualisation

For short- and medium-range pilot-area analysis, the portal samples both ECMWF IFS HRES and NOAA GFS at the selected point and, for facility maps, at each mapped health-facility coordinate.

For future dates, ERA5 is used only as historical context. The current V7 comparison derives day-of-year climatological mean and percentile thresholds from the existing 1981–2014 ERA5 archive used elsewhere in the portal. ERA5 is therefore not described as a future observation. Retrospective model-versus-ERA5 verification remains in the dedicated Forecast verification tab.

The facility temperature/rainfall “gradient” is generated by inverse-distance interpolation of forecast values sampled at facility coordinates. V8 prints forecast values on labelled contour lines and facility names beside the sampled points. It is intended to make within-pilot spatial contrasts easy to interpret. It is not the native ECMWF or NOAA model grid and is labelled accordingly in the interface. Where precipitation is spatially uniform, the app falls back to a point map rather than drawing an artificial gradient. Direct facility values are additionally shown in bar charts and tables.

Brazil facility dropdown labels use the reported CNES establishment name. Numeric CNES type codes are not exposed as user-facing facility names.

## Facility coverage and counting rules

Administrative forecast coverage is fixed by the bundled geography layers: **116 Zambia districts** and **5,572 Brazil municipalities**. Facility drill-down is intentionally enabled for the four REACH pilots only: **Senanga, Sinazongwe, Recife and Palmares**.

The bundled REACH Zambia facility-detail workbook contains **21 Senanga facility records** and **32 Sinazongwe facility records**. These are inventory/detail records. The number of facilities that can be mapped in a live session can differ because a point forecast requires a usable coordinate from the active project/NSDI registry.

Brazil pilot facility counts are read live from CNES/DATASUS and can change as the registry is updated. The Documentation tab includes an explicit refresh control that reports live mapped counts for all four pilots and, where the Zambia NSDI service returns it, the national Zambia facility-registry count.

## Interpretation of administrative and facility statistics

- **District/municipality value:** forecast sampled at the representative point used by the national/state spatial workflow.
- **Administrative min/mean/median/max/range:** summary across the administrative areas displayed in the current national/state map.
- **Facility value:** forecast sampled at the individual facility latitude/longitude.
- **Facility min/mean/median/max/range:** summary across mapped facilities evaluated under the selected parent district/municipality.
- **Facility contour:** visual IDW interpolation of facility point samples; not a native model field.
- **Facility bar chart/table:** direct sampled values, with no interpolation.
- **ERA5 in future comparison:** historical 1981–2014 climatology/threshold context, not a future observation.


## V8 long-range facility-gradient rule

For **Sub-seasonal** and **Seasonal** facility views, the app reuses the ECMWF EC46/SEAS5 physical anomaly series already returned by the facility forecast request. Temperature anomaly (°C) and precipitation anomaly (mm) are averaged over the selected week/month window and visualised at facility coordinates. The app does not make an extra long-range API call solely to draw the gradient.

The long-range contour surfaces use a centred diverging scale because anomalies can be negative or positive. Facility names and contour values are printed on the figure. As with the short-range facility surfaces, these are IDW display surfaces from point samples rather than native model-grid fields.
